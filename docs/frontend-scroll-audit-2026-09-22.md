# 前端界面与滚动核验（2026-09-22）

本轮检查六个主页面、案例详情与编辑界面，覆盖窄屏布局、真实滚轮输入、模拟触摸、键盘导航及页面重绘后的滚动位置。修改已落在 `backend/app/static/index.html`，原始 `_template.html` 保持不变。

## 已修复的问题

| 场景 | 原问题 | 当前行为 |
| --- | --- | --- |
| 手机首页 | 320px 下网格内容撑宽整页 | 卡片和表单允许收缩，整页无需左右移动 |
| 窄窗口导航 | 搜索框挤压标签区域，部分宽度只剩约 49px | 导航独占一行，支持滚轮、鼠标拖动、原生触摸与 Tab 自动显露 |
| 导航手势 | Ctrl/Meta＋滚轮被拦截；拖动取消后状态残留 | 保留浏览器缩放输入，正确清理取消、失焦及移出后的拖动状态 |
| 宽表格 | 横向滚动缺少键盘入口，列宽过窄时文字挤成高行 | 表格局部横滚，支持水平滚轮、Shift＋滚轮和方向键；普通纵向滚轮继续滚动页面 |
| 表格操作 | 打开/收起提醒、排序后回到最左列 | 同一页面重绘保留横向位置，切换主页面回到页面顶部 |
| 手机编辑 | 多零件、任务编辑和提醒配置字段过窄，移除按钮挤占内容 | 按屏幕宽度改为单列或双列，操作按钮和确认区可换行 |
| 提醒日志 | 任务列约 68px、行高约 212px | 保留表格最小宽度，通过横滚查看完整字段，测试数据行高降至约 56px |
| 登录与提示 | 固定顶部偏移与多行页头冲突，短屏提示遮住登录操作 | 根据实际页头高度定位；登录框可内部滚动，320×300 下按钮仍可见可点 |

## 验证结果

- **16 项滚动与布局回归通过**：包括桌面滚轮、横向两端、Shift＋滚轮、键盘、鼠标拖动及取消、模拟触摸、保留滚动位置、短屏登录与动态调整窗口大小。
- **20 项原有前端回归通过**：日期、提交、链接、会话、异步状态、导出和六页面导航等功能保持正常。
- Chromium 布局矩阵：320、390、700、768、960、1280、1440、1920px，共 **64 个页面/宽度组合**，未发现整页横向溢出；纵向滚轮均能到达页面底部并返回顶部。17 个溢出表格检查均能到达左右两端。
- Firefox：1280×800、390×800 下六页面检查通过；长页面纵滚、表格水平滚轮/Shift＋滚轮/方向键、窄屏导航滚轮及 Tab 显露正常，无 JavaScript 错误。
- 多零件提交/编辑、待办编辑、条件批准详情及删除确认另行目检，窄屏内容和操作可达。

所有浏览器请求均由测试数据替代，未访问业务数据库，也未发送真实邮件或 Teams 消息。

## 复测方法

在项目根目录，使用已安装的 Playwright 和 Chromium：

```bash
node backend/tests/scroll-regression.mjs
node backend/tests/frontend-regression.mjs
```

若 Playwright 不在当前 Node 模块搜索路径中，通过 `PLAYWRIGHT_MODULE=/path/to/node_modules/playwright` 指定包目录。可设置 `FRONTEND_ARTIFACT_DIR=/tmp/cockpit-scroll-checks` 保存回归截图；不需要启动后端服务。

本次完整截图与临时矩阵结果保存在 `/tmp/cockpit-scroll-final`、`/tmp/cockpit-scroll-audit/final`，Firefox 结果保存在 `/tmp/cockpit-firefox-check-final.json`；临时目录不作为长期归档。

## 验证边界

结果确认滚动可达、布局适配和交互连续性。触摸检查采用 Chromium 模拟输入，Firefox 的 390px 检查属于窄屏桌面引擎；尚未测量实体设备帧率、触摸惯性，也未验证 Safari。窗口宽度变化验证了重排，Ctrl/Meta＋滚轮验证了缩放输入不被页面拦截，未操作浏览器工具栏逐档验证缩放比例。本轮仅修改本地项目，待用户验收。
