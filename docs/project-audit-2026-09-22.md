# 项目核验与修复记录（2026-09-22）

本轮覆盖前端六个页面、请求边界、审批与待办逻辑、并发写入、SQLite 持久化、管理员会话、通知投递、测试隔离与 Docker 部署。原始 `_template.html` 保持不变。

## 已修复的问题

| 范围 | 原问题 | 修复结果 |
| --- | --- | --- |
| 会议日期 | 台北等时区用 UTC 转换本地日历日期，周三可能变周二；次年日期沿用当前年基准 | 以本地日历生成 ISO 日期，按对应年份计算模板周数；服务端统一日期、周数、标签，确认后保留会议日期和年份 |
| 请求校验 | 任意门禁答案、非法决议、空零件列表、畸形待办和不存在的日期可进入逻辑 | 独立 schemas 模块校验结构、枚举、日期、邮箱、金额、链接和任务 ID；错误返回 422 |
| 链接与页面 | 属性转义不完整、历史危险链接可点击、畸形深链导致脚本异常 | 文本完整转义；只呈现安全 HTTP(S) 链接；无效/已删除的案例链接给出反馈 |
| 页面异步状态 | 登录取消后仍进入管理模式、重复上传、上传失败仍报成功、后台刷新覆盖草稿 | 登录与上传状态受控；保存期间防重复；保留未保存表单；忽略被写入超越的旧快照 |
| 审批并发 | 邮件发送期间删除案例，旧提交单回写覆盖 `Deleted` 状态 | 只合并通知结果，返回当前快照 |
| 管理员会话 | 同时登录丢令牌、中文口令导致 500、更换口令后旧令牌仍有效 | 令牌操作与业务写入共用互斥；口令以 UTF-8 比较；令牌绑定当前口令；bootstrap 验证缓存会话 |
| 提交限流 | 多个并发请求先通过配额检查，突破限制；不活跃 IP 残留 | 配额检查与成功记账位于同一写锁；清理过期条目 |
| 提醒结果 | 嵌套 JSON 原地修改未持久化；较早的投递结果覆盖新提醒 | 深复制后写入，按每次发送标识回填 |
| 提醒规则 | 无效历史日期中断每日检查；延期任务仍逾期；旧编辑覆盖去重字段 | 跳过无效日期但继续其他任务；重算状态；保留服务端提醒元数据 |
| 初始化与编号 | 删空案例后重启重新灌演示数据或主键冲突；删除后复用行号；重复演示导入产生重复任务 | 首次初始化标记落库；持久化编号上限；演示批次分配不冲突的 SWAT 区间 |
| 投递准确性 | Webhook 3xx、SMTP 部分收件人拒收仍报成功；异常可能暴露带凭据 URL | 仅 2xx 算 webhook 成功；部分拒收记失败；共享日志不展示 webhook 异常中的凭据 |
| 部署配置 | 从 backend 启动未读取根目录 `.env`；数据目录 UID 不匹配导致写入失败 | 固定配置文件路径，支持 Compose 用户/组映射；明确单 worker；启动前校验关键配置 |
| 测试与文档 | 测试依赖执行顺序，可能继承真实通道配置；README 与代码脱节 | 用例独立临时库，强制禁用真实外发；锁定 Ruff 开发依赖；更新启动、功能和恢复文档 |

## 复查方法

最终结果：**123 项 Python 测试通过、20 项 Chromium 浏览器回归通过、Ruff 检查通过**。Docker Compose 配置验证、镜像构建，以及非 root 隔离容器内的首页、健康检查、登录、登记、确认、提醒持久化、删除和登出流程均通过。测试依赖产生两条既有弃用提示，不影响测试结果。

浏览器覆盖 `Asia/Taipei`、`America/New_York`、`Europe/Berlin` 三种时区，以及 1440×900 桌面和 390×844 手机尺寸的六页面导航。截图位于 `/tmp/sourcing-cockpit-frontend-audit/`。

```bash
cd backend
uv sync --locked
uv run pytest -q
uv run ruff check app tests
```

浏览器回归使用已安装的 Playwright 与 Chromium，不需要启动服务，所有 API 均为测试替身：

```bash
# 项目根目录；Playwright 可由当前 Node 模块路径找到时
node backend/tests/frontend-regression.mjs

# 安装在其他位置时，将下面的路径替换为实际 Playwright 包目录
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright node backend/tests/frontend-regression.mjs
```

需要保存首页与提交页截图时，可额外设置 `FRONTEND_ARTIFACT_DIR=/tmp/sourcing-cockpit-frontend-audit`。

容器检查使用 `docker compose config --quiet`、`docker compose build`，并在无外网、临时数据目录的独立容器中验证启动和 HTTP 核心流程。测试不连接项目已有数据库，也不发送真实邮件或 Teams 消息。

## 适用范围与保留边界

- 本次令牌格式更新使原管理员会话失效，重新登录即可；业务数据无需迁移。
- 当前设计仍为单 worker、SQLite、小团队共享应用。同一案例多人同时编辑以最后一次保存为准。
- Legacy Excel Upload 仍是演示数据生成器；实际文件解析需另行实现。
- 历史种子数据缺少会议年份，完整跨年统计/筛选需要数据迁移与业务口径确认；本轮修正新提交的日期信息，不替历史数据猜年份。
- SMTP / Teams 已覆盖模拟成功、失败及未配置场景，真实外发效果需在 IT 提供配置后联调。`sent` 表示上游接受，不表示收件人已读。
- 本轮未发布到正式环境。当前工作目录没有 Git 元数据，无法生成提交或 Git 差异；修改前源码备份位于 `/tmp/sourcing-cockpit-before-audit-20260922-125505.tar.gz`，临时目录不作为长期备份。
